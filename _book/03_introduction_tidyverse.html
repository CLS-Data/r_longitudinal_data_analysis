3  An Introduction to the tidyverse

3.1 The tidyverse Philosophy

The tidyverse is a collection of packages that cover most of the central tasks of data science, from opening data files, to cleaning variables, producing descriptive and inferential statistics, and presenting results in tables and plots. The tidyverse is developed by Hadley Wickham and colleagues at Posit (the developers of RStudio). The main tidyverse packages can be installed using the install.packages("tidyverse") function. Calling library(tidyverse) loads the “core” tidyverse packages, a subset of those installed by install.packages("tidyverse"). The “core” tidyverse packages are ggplot2, dplyr, tidyr, readr, purrr, tibble, stringr, forcats, and lubridate. Collectively, these cover the most common data science tasks, but we will need to load a few extra, as and when. Note, some of the core packages also load specific functions from other tidyverse packages (notably the magrittr %>% pipe operator; see next section).

# install.packages("tidyverse")
library(tidyverse)

tidyverse packages work seamlessly together because they follow a common design philosophy. As this philosophy is public and well-documented, other developers can write packages that fit within the tidyverse ecosystem (and do). The two main features of the tidyverse philosophy are incrementalism and tidy data.

3.1.1 Incrementalism (and the %>% pipe)

tidyverse functions are generally designed to do one thing. If a function requires data to be prepared in a specific way, it is typically expected this will be done prior using separate functions. tidyverse functions have simple descriptive ‘verb’ as names - for instance, select() to choose columns from a tibble, filter() to retain specific rows, and mutate() to add or edit columns. This single-purpose philosophy makes it easier to read and write tidyverse code as decomposes complex processes into a sequence of relatively simple steps.

To facilitate incrementalism, the tidyverse makes heavy use of the pipe (%>%) operator (from magrittr). The pipe works as follows: it takes the object produced on its left hand side and puts it into the first argument of the function on its right hand side. This is best explained by example:

c(1, 2, 3) %>% mean()
[1] 2

In this command, R first creates the vector c(1, 2, 3) then puts it into the first argument of the mean() function.

Pipes can be chained together. For instance:

c(1, 2, 3) %>% 
  mean() %>% 
  paste("is the mean value")
[1] "2 is the mean value"

A series of pipe operations can be read as “do this, then do this, then do this…”. Observe that the above is easier to read than:

paste(mean(c(1,2,3)), "is the mean value")

To be compatible with the pipe operator, tidyverse functions are designed to take the data to be operated on as their first argument. Note, sometimes (particularly when using non-tidyverse functions), the relevant argument is not the first. In which case, one can use the dot (.) placeholder within the function call to indicate where the piped object should go.1 For instance:

c(1, 2, 3) %>% 
  mean() %>%
  paste("The mean value is", .)
[1] "The mean value is 2"

3.1.2 Tidy Data

The second main feature of the tidyverse philosophy is tidy data. As noted, most tidyverse functions are designed to take data as their first input and many output data, too. tidyverse functions generally operate on tibbles, with the expectation they are structured in a tidy way. Tidy data is data where each variable is in its own column, each observation is in its own row, and each value is in its own cell - in LDA settings, this generally means “long format”, with one row per person-sweep, though we will see other structures in the course, too. Tidy data is useful because it work works well with R’s vectorised structure. More on tidy data can be read in Wickham (2014).

3.1.3 A Warning: Continuous Development

The tidyverse is under continuous development, and the developers are predisposed to tinker, withdrawing or retiring functions that no longer fit with their (developing) philosophy. They are also opinionated, choosing to restrict functions to encourage safe practices (for instance, in the last chapter, we saw how tibbles do not use recycling of vectors of length greater than 1). It is advisable to keep up to date with changes to the tidyverse. The tidyverse blog is a good place to start.

How could the following command be written using the (%>%) pipe?

3.2 Some Useful tidyverse Functions

There are several tidyverse functions we will use repeatedly in this course. We’ll introduce these here, and discuss more advanced ways of using them in later sessions.

3.2.1 glue::glue()

Above we constructed a string from R objects using paste(). The glue package (a non-core tidyverse package) provides multiple functions for constructing strings, but with more user-friendly interfaces. The package’s main function glue() uses curly braces ({}) to indicate where R objects should be inserted into a string. For instance:

library(glue)
glue("The mean of 1 to 10 is {mean(1:10)}")
The mean of 1 to 10 is 5.5

glue() syntax is also used in multiple other functions in the tidyverse. For instance, we will use when reshaping data from wide-to-long and from long-to-wide.

3.2.3 tibble::tibble()

As discussed, tibbles are the tidyverse’s version of data.frames. They differ from data.frames in a few key ways:

  • They do not convert character vectors to factors by default.
  • They do not allow partial matching of column names when using the $ operator.
  • They have a cleaner print() method that shows only the first 10 rows and as many columns as fit on the screen.
  • They do not use recycling of vectors of length greater than 1 when assigning values to columns.
  • Subsetting a tibble with [rows, columns] syntax always returns a tibble

tibbles can be created from scratch using the tibble function and data.frames can be converted to tibbles using the as_tibble() function. A nice characteristic of the tibble function is that columns just created can be used to create other columns within the same function call.

tibble(
  x = 1:3,
  y = x^2,
  z = y + 2
)
# A tibble: 3 × 3
      x     y     z
  <int> <dbl> <dbl>
1     1     1     3
2     2     4     6
3     3     9    11

The tibble package contains a few other helpful functions, including:

  • tribble(): for creating small tibbles in a row-wise fashion.
  • enframe() and deframe(): for converting named vectors or lists to tibbles and vice-versa.
  • as_tibble_row(): for converting vectors to single-row tibbles.
  • lst: for creating lists using just-created sub-objects similar to tibble().

Multiple statements can be passed to filter() and filter_out() using multiple arguments. These are evaluated at the same time, rather than sequentially, so are equivalent to writing statement_1 & statement_2 & .... Thus the following gives the same result - mean(GCBMIN7) is evaluated before any filtering is done:

mcs_17y %>%
  filter(GCMCS7AG >= 18,
         GCBMIN7 > mean(GCBMIN7))

mcs_17y %>%
  filter(GCBMIN7 > mean(GCBMIN7),
         GCMCS7AG >= 18)

If you want to ensure the statements are evaluated sequentially, you can chain multiple filter() calls together using the pipe operator.

To combine multiple statements with an OR, the “|” operator or when_any() function can be used. Below we get individuals who are either age 18 or older or have above average BMI.

mcs_17y %>%
  filter(GCBMIN7 > mean(GCBMIN7) |
           GCMCS7AG >= 18)

mcs_17y %>%
  filter(when_any(GCBMIN7 > mean(GCBMIN7),
                  GCMCS7AG >= 18))

Note, this code is not quite right because the MCS .dta files use negative values for missing data (e.g., -1 = "Not Applicable"), and these values have been used when calculating mean(GCBMIN7). Later, we will see ways of handling these negative values appropriately, but one solution is simply to filter out the offending rows. Note, one special type of filter() operation is to retain rows with observed (i.e., non-NA) values for specific columns. This can be achieved using the drop_na() function.

3.2.6 dplyr::mutate()

The mutate() function is used to create new - or overwrite existing - columns in a tibble. The new column can be a function of other columns, and can be used to make other columns within the same function call. Below we create two new columns for age-squared and BMI multiplied by age-squared. Unlike filter(), mutate() works sequentially.

mcs_17y_mini %>%
  mutate(age_sq = GCMCS7AG^2,
         bmi_x_age_sq = GCBMIN7*age_sq)

A helpful function to use within the mutate() function is ifelse(). The value ifelse() returns depends on whether a Boolean expression is TRUE or FALSE for a given observation. Below we create two new variables, bmi and obese. The former contains the values of GCBMIN7 with negative values recorded as missing. The latter is a binary variable equal to 1 if the individual’s BMI is greater than 30, and 0 otherwise.

mcs_17y_mini %>%
  mutate(bmi = ifelse(bmi >= 0, GCBMIN7, NA),
         obese = ifelse(bmi >= 30, 1, 0)) %>%
  select(GCBMIN7, bmi, obese)

Note, NAs are propagated through ifelse() (i.e., if bmi is NA, then obese will also be NA).

More complex decision rules can be implemented with the dplyr::case_when() function. This sets the value for an element depending on which of a series of conditions is met. We can use this can to create a BMI category variable and handle the negative value missing codes correctly.

mcs_17y_mini %>%
  mutate(
    bmi_category = case_when(
      GCBMIN7 < 0 ~ NA,
      GCBMIN7 < 18.5 ~ "Underweight",
      GCBMIN7 >= 18.5 & GCBMIN7 < 25 ~ "Normal weight",
      GCBMIN7 >= 25 & GCBMIN7 < 30 ~ "Overweight",
      GCBMIN7 >= 30 ~ "Obese",
      TRUE ~ NA
    )
  ) %>%
  select(GCBMIN7, bmi_category)

The last line in the case_when() function (TRUE ~ NA) handles any cases missed by the preceding conditions, setting them to NA. It is actually not necessary here as case_when() sets elements meeting no conditions to NA by default.

mutate() adds columns or modifies existing columns and retains the rest. To keep only the new or modified columns, use the transmute() function instead.

3.2.7 dplyr::summarise()

As the name suggests, summarise() is used to summarise data within a tibble. It returns a single row of data and discards other variables.2 Below we use summarise() to return the mean BMI in the dataset setting the mean() argument na.rm = TRUE to ignore missing values. Notice how we can use the pipe within the summarise() function call.3

mcs_17y_mini %>%
  summarise(mean_bmi = ifelse(GCBMIN7 >= 0, GCBMIN7, NA) %>%
              mean(na.rm = TRUE))
# A tibble: 1 × 1
  mean_bmi
     <dbl>
1     23.3

Multiple variables can be produced in the same summarise() function call. Like mutate(), these are evaluated sequentially. Given this, one must be mindful of the current state of a column if it is used in multiple places within summarise().

mcs_17y_mini %>%
  mutate(bmi = ifelse(GCBMIN7 >= 0, GCBMIN7, NA)) %>%
  drop_na(bmi) %>%
  summarise(mean_bmi = mean(bmi),
            min_bmi = min(bmi),
            max_bmi = max(bmi))
# A tibble: 1 × 3
  mean_bmi min_bmi max_bmi
     <dbl>   <dbl>   <dbl>
1     23.3    11.0    49.4

3.2.8 dplyr::group_by()

group_by() is used to greated a grouped tibble where operations calculations are carried in each group of rows separately. group_by() is perhaps easier to explain by example. Below I group mcs_17y_mini by GCOBFLG7 to get the mean BMI within each BMI category. The results is a single tibble with one row for each BMI category.

mcs_17y_mini %>%
  group_by(GCOBFLG7) %>%
  summarise(mean_bmi= ifelse(GCBMIN7 >= 0, GCBMIN7, NA) %>%
              mean())
# A tibble: 4 × 2
  GCOBFLG7                                    mean_bmi
  <dbl+lbl>                                      <dbl>
1 -1 [Not applicable]                             NA  
2  0 [Not overweight (including underweight)]     20.8
3  1 [Overweight]                                 26.7
4  2 [Obese]                                      33.6

It is possible to group by multiple variables. To ungroup a grouped tibble, use the ungroup() function. By default, summarise() ‘peels off’ the last grouping variable, so group_by(GCOBFLG7) %>% summarise() returns an ungrouped tibble. Other behaviours can be specified with the .groups argument.

Not, where an operation in mutate() returns a single value, the value is automatically recycled across rows. mutate() can therefore be used to create group-level variables. One important LDA model is the Random Effects Within Between (REWB; Bell et al., 2019) model, which includes both within-unit (person differences) and between-unit (person averaged) variables. Below we use mutate() with group_by() to create both.

mcs_17y_mini %>%
  group_by(MCSID) %>%
  mutate(
    bmi = ifelse(GCBMIN7 >= 0, GCBMIN7, NA),
    bmi_between = mean(bmi, na.rm = TRUE),
    bmi_within = bmi - bmi_between

  ungroup() %>%
  select(MCSID, GCBMIN7, bmi, bmi_within, bmi_between)

ncds_55y_mini %>%
  mutate(bmi = ifelse(bmi >= 0, bmi, NA)) %>%

  group_by(region) %>%

3.2.11 purrr::map()

Often, you will need to apply the same operation to a similar set of objects - for instance, you may wish to load multiple datasets, to clean several variables in the same way, or to run many regression models (e.g., varying the outcomes or sets of covariates). Writing this out for each object separately is time-consuming, error-prone and not adaptable to changes.

The purrr package (a core tidyverse package) provides a suite of functions for repeating yourself in R. The main function map() takes two arguments: a set of objects one wishes to repeat a function for, and the function to be repeated. map() function calls can be written in a few different ways, but in this course we will predominantly use ‘lambda’ notation. Below, we use map() to open three MCS datasets and to calculate the number of rows in each.

c("mcs1_cm_derived.dta",
  "mcs1_family_derived.dta",
  "mcs1_parent_derived.dta") %>%
  map(
    ~ glue("{mcs_fld}/0y/{.x}") %>%
      read_dta() %>%
      nrow()
  )
[[1]]
[1] 18786

[[2]]
[1] 18540

[[3]]
[1] 33884

In this map() call, .x stands as a placeholder for current value of the object being looped over. When passed a vector, map() loops over each element of the vector in turn, so in first case, .x = "mcs1_cm_derived.dta", in the second case, .x = "mcs1_family_derived.dta", and in the third case, .x = "mcs1_parent_derived.dta". Each time, map() takes the current value of .x, inserts it into the glue() function, reads in the relevant dataset, and calculates the number of rows.

For tibbles, map() loops over columns. If you unsure how map() splits a particular object, map(.x, ~ .x) will return the inputs back, split whichever way they have been.

map() always returns a list. If the input is named, the output will be named, too. There are variants of map() that return other object types. For instance:

  • map_dbl() returns a numeric vector
  • map_int() returns an integer vector
  • map_chr() returns a character vector
  • map_lgl() returns a logical vector
  • map_dfr() returns a tibble appending the results together by row (with dplyr::bind_rows()).
  • map_dfr() returns a tibble joining the results together by column (with dplyr::bind_cols()).

map() only loops over a single input. map2() (and its variants) loop over two inputs, side by side. Its syntax is similar to map() but uses two placeholders, .x and .y (i.e., map2(.x, .y, ~ f(.x, .y))). pmap() (and its variants) generalise this still further to multiple inputs. Instead of .x or .y as placeholders, it uses ..1, ..2, and so on. pmap() takes a list of inputs as its first argument (pmap(list(..1, ..2, ...), ~ f(..1, ..2, ...)).

purrr also contains other useful functions, including reduce(), which we will see later in this course.

3.3 Putting It All Together

We have intimated at some of the complexity that can be achieved with the tidyverse by piping individual functions together. Below, we chain several to identify cohort members who have appeared in each sweep of the MCS and find to the difference in mean BMI between sweeps 6 and 7 among this balanced panel, using less than twenty lines of code. We use a tidyselect helper, matches(), to select some columns based on a regular expression - used alongside col_select(), this loads a variable if it matches the regular expression, and doesn’t crash if not matching variables are found. We delay discussing matches() and regular expressions until later chapters.

map_dfr(
  1:7,
  ~ glue("{mcs_fld}/{mcs_fups[.x]}y/mcs{.x}_cm_derived.dta") %>%
    read_dta(col_select = c("MCSID", matches("^([A-G]CNUM00|GCBMIN7|FCBMIN6)$"))) %>%
    rename(CNUM = matches("^[A-G]CNUM00$")),
  .id = "wave"
) %>%
  add_count(MCSID, CNUM) %>%
  filter(n == 7) %>%
  mutate(bmi = case_when(
    FCBMIN6 >= 0 ~ FCBMIN6,
    GCBMIN7 >= 0 ~ GCBMIN7
  )
  ) %>%
  drop_na(bmi) %>%
  group_by(wave) %>%
  summarise(mean_bmi = mean(bmi)) %>%
  mutate(diff_mean_bmi = mean_bmi - lag(mean_bmi))

2 7         23.2          1.86
