5.1 Advanced Functions for Data Cleaning

5.1.1 tidyselect Helpers

In Chapter 3, we used select() to retain or drop variables from a tibble. We saw the manual way of doing this (specifying each variable separately), as well as a more programmatic way: using a tidyselect helper, matches(), that selected every variable whose name matched a regular expression. matches() is one of many tidyselect helpers:

  • matches(): selects variables based on regular expressions (e.g., matches("^G") selects any variable starting "G").
  • x:y: selects variables location between x and y (inclusive). x and y can be variable names and/or positions. last_col() is another useful helper that can be used in this context (e.g., age:last_col() selects every column from age to the last column).
  • where(): selects variables based on a logical condition - this condition is applied to the values not the variable names. For example, where(is.factor) selects all factor variables.
  • all_of(): selects all variables specified in a character vector (e.g., all_of(c("sex", "age") selects columns sex and age). Note, all_of() throws an error if not all of the specified variables are present in the tibble.
  • any_of(): returns any variables specified in a character vector that are available in a tibble. Unlike all_of(), any_of() does not throw an error if a specified variable is not present.
  • everything(): selects every column in a tibble. This may seem redundant, but we will see contexts in which it is useful.

tidyselect helpers can be combined with the & (AND) and | (OR) operators, while the ! (NOT) operator can be used to identify variables that do not meet a condition. For example, where(is.numeric) & !matches("^G") selects all numeric variables that do not start "G". Below is some example code.

tidyselect helpers can be used in many functions in the tidyverse beyond select(). For instance, they can be used to specify columns in drop_na(), in the col_select = ... argument of read_dta(), in the .cols = ... argument of rename_with(), and in across() (more on which below).

tidyselect helpers are not just useful for selecting raw variables en masse, but can also be used with cleaned variables too. This is made easier if care is taken to name cleaned variables consistently. For instance, naming BMI variables in a ‘wide’ dataset in a consistent way (e.g., bmi_03, bmi_05, …, bmi_17) allows one to use a simple regular expression (matches("^bmi_\\d\\d$")) to select them. Later, we will use vectors that specify control variables to be used in regression models and select them with all_of().

5.1.2 dplyr::rename_with()

Variables can be renamed en masse using rename_with(). rename_with() applies a function to each variable name in turn. Functions can be specified using the lambda notation we used in Chapter 3 with purrr:map(). The stringr package contains several functions that can be used inside rename_with, including str_replace() (to replace part of a string with another string), str_remove() (to remove part of a string), str_to_lower() (to put strings in lower case), and str_sub() (to extract characters between specified positions in a string; e.g., str_sub(x, 2, -2) extracts the second to penultimate letters of x). glue::glue() can also be handy. Here are some examples:

mcs_17y %>%
  rename_with(str_to_lower) %>% # Equivalent to ~ str_to_lower(.x)
  rename_with(~ str_remove(.x, "^g")) %>%  # Removes sweep-specific prefix "G"
  rename_with(~ glue("{.x}_17"),
              .cols = -c(mcsid, cnum00))

Notice the line rename_with(str_to_lower) - when just a function name is specified, the column will be placed in the first argument of that function. This syntax can also be used in purrr::map(). Note, rename_with(~ str_remove(.x, "^G")) is an essential preparatory step if one wishes to append data from different sweeps of the MCS together.

5.1.4 dplyr::across()

across() allows one to apply a function to multiple variables in turn. It is most typically used in mutate() to transform multiple variables in the same way. A key use of across() in LDA is to replace negative values representing missing codes with R’s NA missing value. In Chapter 3, we used ifelse() to recode negative values, but this drops variable metadata (e.g., value labels) that we may wish to keep. To recode missing values while retaining other metadata, we can use functionality from the labelled package as in the negative_to_na() function below. We apply this to all labelled variables (where(is.labelled)) using across().

negative_to_na <- function(x){
  na_range(x) <- c(-Inf, -1)
  user_na_to_na(x)
}

5.1.6 dplyr::if_any() / dplyr::if_all()

if_any() and if_all() are similar to across() in that they apply a function to multiple variables at once. They differ in that the function aggregates the results to return a single logical vector. Both if_any() and if_all() are vectorised. if_any() returns TRUE if the function returns TRUE for any of the variables, while if_all() returns TRUE if the function returns TRUE for all of the variables. if_any() and if_all() are most typically used in filter(), but can also be used in mutate().

5.1.7 dplyr::pick()

Sometimes we may want to perform a function using several columns simultaneously - for instance, for a mental health measure, to sum the values across several columns into a total Likert score. Base R contains several functions for carrying out row-wise operations, including pmin(), pmax(), rowSums() and rowMeans(), but these functions are not pipe-friendly as, although they use data.frames or tibbles as inputs, they operate on every column (which may include more columns than one wants) and output a single vector, rather than a transformed tibble. pick() instead allows one to specify the correct columns to put into these functions and place them within a pipe. In essence, pick() takes the current tibble and temporarily creates another which has just the columns specified. tidyselect helpers can be used to specify columns.1

5.2 Writing Functions to Clean Data

As has been discussed, cleaning data is often a repetitive process in LDA: we may need to clean the same variables in the same way across different sweeps. In this case, to make our code efficient and less error-prone, we can write bespoke functions. Below is a function that cleans height and weight data and derives BMI in each of sweeps 3-7 in the MCS. As we saw in Chapter 4, height and weight are contained in the variables XCHTCM00 and XCWTCM00 in each of these sweeps (or XCHTCMA0 and XCWTCMA0 for Sweep 5). This makes the cleaning predictable.

mcs_fups <- c(0, 3, 5, 7, 11, 14, 17)

clean_bmi <- function(sweep){
  sweep_letter <- letters[sweep]
  fup <- mcs_fups[sweep]
  glue("{mcs_fld}/{fup}y/mcs{sweep}_cm_interview.dta") %>%

5.3.1 Merging tibbles with dplyr::*_join()

To merge two tibbles together - i.e., to create a new tibble with columns from both tibbles - we can use the dplyr mutating *_join() functions. These are called mutating joins because they add new columns to the outputted tibble. The functions differ in the rows that each retain in the output tibble.

  • full_join(x, y, by = ...): Returns all rows from x and y . The missing value NA is used to fill cells that are created during the merge. Rows in x with no match in y will have NA values in the new columns from y. Rows in y with no match in x will have NA values in the columns of x.
  • inner_join(x, y, by = ...): Returns all rows from x and y where there are matching rows in both tibbles.
  • left_join(x, y, by = ...): Returns all rows from x Rows in x with no match in y will have NA values in the new columns from y.
  • right_join(x, y, by = ...): Returns all rows from y, and all columns from x and y. Rows in y with no match in x will have NA values in the columns of x.

To join the two datasets together, we need to specify the columns to join by (the “key” variables). By default, *_join() functions will use all variables with common names across the two datasets as the key variables. To specify particular columns, we can instead provide a character vector of the joining columns to the by argument. Joining columns do not need to have the same name in each tibble. If they have different names, we can specify a named vector. The names of this vector are names of the columns in the left (x) tibble and the values of the vector are the names of the columns in the right (y) tibble. In the merged tibble, key columns retain the names from the left tibble. Let’s see the functions in action:

5.3.1.1 Merging 2+ tibbles with purrr::reduce()

What if we want to merge more than two datasets together - for instance, merge all seven sweeps of the MCS? Writing out each *_join() function separately would be cumbersome. Instead, we can use purrr::reduce() to chain together successive *_join() function calls, aggregating the result.

reduce() is similar to map() in that repeats a function for each object within an input. But unlike map(), the result from an iteration back into the next iteration. Specifically, reduce() takes an object, applies a function, f, to the first two element and then takes the result and inputs it into f along with the next element of the inputted object, repeating this until the object is exhausted. For instance, specifying inner_join() in reduce() with a list of three tibbles will perform inner_join() on the first two, and then perform inner_join() on the result from that with the third tibble.

The syntax for reduce() is similar to map2() where .x and .y refer to the first and second elements of the list, respectively, or to the result and to the next element of the list. 5.5.1 tidyr::complete()

While pivot_wider() makes implicit values explicit, bind_rows() does not. It is possible to create missing rows when data are in long format by using tidyr::complete(). This function is straightforward - you pass it a tibble and then specify the columns one wishes to get every combination for (here the ID and time variables). By default, other columns will be filled with NA values in the newly created rows. This behaviour can be overridden using the fill argument.

One issue with MCS data is that ID columns are spread over two variables. Making all combinations of MCSID and CNUM00 creates CNUM00 == 2 values for each MCSID, even if they are singleton families. This problem can be avoided first uniting (unite()) the ID columns then separating (separate()) them after using complete().

df_long_mini %>%

5.5.2 tidyr::fill()

fill() allows one to fill in missing values in a column with observed values appearing above or below. This is particularly useful when a time-invariant variable is only available for a person in some survey sweeps, or where such an assumption about time-invariance is justified. For instance, in tobacco research, the conservative Russell Standard (West et al., 2005) is sometimes used which assumes that smokers who drop-out of a survey continue to smoke. Another example is adult height, which is often only collected from those for whom data is not already available (e..g, as in the NCDS), and can be assumed to be stable over adulthood. Available measures can therefore be used to deterministically impute the missing values.

The fill() function is straightforward. One passes it a tibble (possibly grouped) and the columns to fill, along with the direction to fill values (using argument .direction): down, up, downup, or updown. Below we use complete() to make missing sweeps explicit, then fill the missing height values with the last observed one for that individuals.

df_long_mini %>%
